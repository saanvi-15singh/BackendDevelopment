## 2. Introduction

Serverless Architecture is a cloud computing model in which developers can build and run applications without directly managing servers. The cloud service provider manages the infrastructure, server maintenance, scaling, and resource allocation.

Function as a Service (FaaS) is an important part of serverless computing. It allows developers to execute small pieces of code called functions whenever a particular event occurs.

In this assignment, we explore the concept of Serverless Architecture, its event-driven nature, working mechanism, advantages, limitations, and practical applications.

## 4. Understanding Serverless Architecture

Serverless Architecture is a cloud-based application development approach where developers focus on writing application code instead of managing servers.

The cloud provider automatically handles:

- Server provisioning.
- Infrastructure management.
- Resource allocation.
- Automatic scaling.
- Availability and maintenance.

### Function as a Service (FaaS)

FaaS allows developers to write individual functions that execute in response to events.

For example, when a user submits a form, an event is generated. This event triggers a serverless function, which processes the information and returns a response.

AWS Lambda is a popular example of FaaS.

## 5. Event-Driven Architecture

Serverless applications generally follow an event-driven architecture.

An event is an action or occurrence that triggers a particular function.

Examples include:

- A user submitting a form.
- A file being uploaded.
- An HTTP request being received.
- A database record being updated.
- A scheduled task being executed.

### Working Process

1. An event is generated by a user or application.
2. The event is received by the cloud service.
3. The corresponding serverless function is triggered.
4. The function executes the required logic.
5. The function generates and returns the output.

## 6. SaaS, PaaS and FaaS

| Feature | SaaS | PaaS | FaaS |
|---|---|---|---|
| Full Form | Software as a Service | Platform as a Service | Function as a Service |
| Purpose | Provides ready-to-use software | Provides an application development platform | Executes individual functions |
| Server Management | Provider managed | Provider manages underlying infrastructure | Provider managed |
| User Responsibility | Using the software | Developing and deploying applications | Writing and deploying functions |
| Example | Gmail | Google App Engine | AWS Lambda |

## 7. AWS Lambda

AWS Lambda is a serverless computing service provided by Amazon Web Services (AWS).

It allows developers to execute code without provisioning or managing servers.

### Important Features

- Automatic scaling according to incoming requests.
- Event-based execution.
- Pay-per-use pricing model.
- Support for multiple programming languages.
- Integration with other AWS services.
- Automatic infrastructure management.

### Working of AWS Lambda

1. A developer writes a function.
2. The function is uploaded to AWS Lambda.
3. An event source triggers the function.
4. AWS Lambda executes the code.
5. The result is returned or passed to another service.

## 8. Practical Implementation: Student Result Processor

### Project Overview

For the practical demonstration, a simple application called **Student Result Processor** is used.

The application demonstrates how a serverless function processes student information after receiving an HTTP request.

The application collects three inputs:

- Student Name
- Subject
- Marks

When the user clicks the **Trigger Serverless Function** button, an HTTP POST request is generated and sent to the function named `processResult()`.

The function processes the received information and returns a JSON response.

## 9. Advantages of Serverless Architecture

1. **No Server Management:** Developers do not need to manage physical or virtual servers.
2. **Automatic Scaling:** Resources automatically adjust according to application requirements.
3. **Cost Efficiency:** Users generally pay according to actual execution and resource consumption.
4. **Faster Development:** Developers can concentrate on application functionality.
5. **High Availability:** Cloud providers manage infrastructure availability.
6. **Event-Driven Execution:** Functions execute when specific events occur.

## 10. Limitations of Serverless Architecture

1. **Cold Start:** Functions may experience additional startup time after periods of inactivity.
2. **Vendor Lock-in:** Applications may become dependent on a particular cloud provider.
3. **Execution Limits:** Cloud providers impose execution time and resource limits.
4. **Debugging Complexity:** Monitoring and debugging distributed functions can be challenging.
5. **Internet Dependency:** Cloud-based applications generally require network connectivity.
6. **Limited Control:** Developers have less control over the underlying infrastructure.

## 11. Real-World Applications

Serverless Architecture is used in several real-world applications:

- **File Processing:** Automatically processing uploaded images and documents.
- **E-commerce:** Processing orders and sending notifications.
- **Chat Applications:** Handling messages and real-time events.
- **Data Processing:** Processing incoming data streams.
- **Web Applications:** Handling API requests and form submissions.
- **Scheduled Tasks:** Running automated tasks at specific intervals.
